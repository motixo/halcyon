Candidate actionable defensive improvement: ensure cancelling Arrange can release keyboard/fullscreen input even when rollback fails, while retaining and displaying recovery information elsewhere. Product changes are owned by the parent, and none is made here. This should not be sold as the hour-long RX590 fix without the missing reproduction.

Additional source limit: `config.rs:1285` and `desktop/store.rs:1886` use blocking `flock(LOCK_EX)` without a time limit. Some UI arrangement/settings handlers call store operations synchronously. A live external lock holder could therefore stall that client, especially troublesome while an exclusive input surface is active. Inspected transactions take config lock before desktop lock consistently; no inverted lock-order/self-deadlock or actual stalled holder was found. This is a conditional failure mechanism, not an established reporter reproduction. Capture `/proc/PID/wchan`, stack where permitted, lock ownership and compositor state at an incident before attributing it.

## Implementation corrections

Settings scene preparation and wallpaper color analysis now share two cancellable
image workers. Requests and results are bounded; obsolete queued requests are
coalesced. A new selection cancels old decoding, while existing request IDs and
file revisions prevent stale delivery from replacing the current preview.

The worker starts before application migration or toolkit initialization and
writes no configuration. It has memory, CPU and wall-time limits. Cancellation,
timeout and dropped caller futures retain their worker slot until the exact child
is killed and reaped. Parent death also terminates the child. Review found and
fixed the dropped-future ownership gap before acceptance.

This covers scene and color-analysis decoding. Other legacy Wallpaper-gallery
jobs and the later aggregate image budgets remain separate work.

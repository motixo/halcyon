Components & rendering

The same components in preview and on the desktop.

What supports it

Reuse native views and their measurements. Preview contexts use sample data and cannot operate live tools.

03

Layout & input

Correct sizes, displays and clickable areas.

What supports it

Preserve measured geometry, display identity, fallback intent and recovery. Introduce stable instances before duplication.

04

Data & actions

Shared data without duplicate work.

What supports it

Share provider work by full binding key. Handle stale data and cancellation; previews create no live subscriptions.

05

Apply & automation

One guarded path for changes and Undo.

What supports it

Retain transactions, native adapters and recovery. Design Moments around existing event and manual-change rules.

06

Assets & sharing

Portable designs with honest fallbacks.

What supports it

Bound files and rendering costs; keep accounts/content local. Qualify image depth and richer packages separately.

# FB06 — shared Clock and Weather presentation

Clock and Weather now use explicit presentation inputs for both desktop rendering and local previews. This is the second implementation task in the foundation slice. It does not introduce providers, persistent widget instances or a new renderer.

## Implemented

- Clock resolves its face, fonts, colors, time and geometry before drawing. Measurement uses the same resolved fonts as rendering, including Daily overview's font overrides. Analog sizing no longer depends on fitting an invisible digital time string.
- Weather projects readings, forecast dates, failure/age text and style into an owned presentation. Drawing reads neither the provider nor the current clock. Forecast output remains bounded to three days.
- Layout, runtime and preview adapters share Clock and Weather's natural sizes. Viewports are finite; resize minimums remain owned by existing layout policy.
- Clock and Weather in setup scenes now use their real components. Selecting analog changes the miniature dial as well as the desktop widget. Other scene widgets remain illustrative.
- Local Weather previews have no live location action. Scene thumbnails consume no input; their surrounding navigation controls retain the existing behavior.
- Weather retains the same native card root as the other desktop cards, preserving native state when cards are reordered.

No preference schema or migration changed in FB06. Digital/analog and surface choices remain independent of style: Paper and Tidal can use either face. Tidal and Paper here are presentation fixtures, not the finished preset collection planned for FB10.

## Acceptance

The [evidence record](evidence/fb06-20261026.json) contains exact source and artifact hashes, regression results, captures and measurement limits. Reproduction commands are in [probes/README.md](probes/README.md).

98 distinct focused regressions pass, including eleven new cases. The new cases cover frozen inputs, resolved-font measurement, finite bounds, minimum/portrait/wide geometry, live/preview pixel parity, Weather states and scrolling, disabled preview actions, card reorder state, and the selected Clock face in setup thumbnails. Output-scale checks exercise 100%, 150% and 200% rendering; these are not physical mixed-DPI acceptance. One existing look-export diagnostic remains ignored. The coordinated installation thread's final 32 passing tests are recorded separately.

Actual native component and Settings captures cover both styles and both Clock faces, with compact and wide Settings windows. The separate real-window probe uses a private nested COSMIC session. Performance samples include synchronous screenshot readback, so they are a rendering proxy, not compositor input-to-present latency.

Across Clock, Weather, Daily overview and Themes, 320 warm GPU samples gave per-case p95 values of 0.97–3.36 ms; 48 software samples gave 7.82–12.63 ms. Event dispatch stayed below 0.69 ms at p95. These meet the recorded 4 ms GPU, 15 ms software and 1 ms dispatch proxy budgets on this workstation. Owned AMD GPU engine activity was observed during the offscreen probe.

The ordinary release build opened Clock, Weather and Themes in the private compositor. Each 12-second static sample recorded no CPU-tick increment at 10 ms granularity, with 225.7–264.8 MiB RSS. This is a short smoke observation, not the 60-second idle-budget or long-session qualification. Fixture preferences stayed byte-identical and owned processes exited. The persisted Paper/analog fixture also rendered the correct analog Clock in the Themes scene.

Formatting and scoped whitespace checks pass. The five preexisting wizard-repair file hashes are preserved. Existing build warnings remain; the old test-used Clock label helper also now emits a release dead-code warning.

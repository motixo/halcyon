# Published Updates integration and APT contract

Halcyon **0.2.5 already contains** the Updates row, running-installation identity
checks and asynchronous manual PackageKit adapter. The earlier pending Rust/UI
handoff is historical. This APT task does not rebuild or modify those binaries.

`src/settings/updates/identity.rs` checks the actual running executable and dpkg
ownership/checksums, not another installation on PATH. Its `SOURCE_TEXT` and
`PREFS_TEXT` are exact byte expectations. The bootstrap builder preserves them:
`noble/main`, `amd64`, `https://profilaz3.github.io/halcyon/apt`, scoped
`/usr/share/keyrings/halcyon-archive-keyring.gpg` and the four exact package pins.
It also supplies `DEBIAN/md5sums`, required by the published app to verify the
owned public keyring. A focused Python test reads the unchanged Rust constants,
compares the generated bytes and verifies packaged checksums without Cargo.

The installed channel remains Apt only when those ownership/configuration checks
pass. Manual package users can open enrollment information; source/unknown builds
remain distinct. Enrollment information can keep linking to
[DISTRIBUTION.md](DISTRIBUTION.md). No app update is needed just to activate the
published explicit enrollment path.

The adapter uses the installed noble PackageKit system-bus interface
`org.freedesktop.PackageKit`, `CreateTransaction`, then separate
`RefreshCache(false)` and `GetUpdates(2)` transactions. It subscribes before calls,
uses bounded asynchronous operations/request tokens/cancellation and reports
failure rather than treating stale data as a successful fresh check. PackageKit
and COSMIC Store own privileged transactions/authentication. There is no app-owned
binary updater or password collector.

The verified Store launch is desktop entry `com.system76.CosmicStore.desktop`,
`Exec=cosmic-store %u`, with no argument. The UI says **Open COSMIC Store**, then
**choose Updates**. Inspected upstream Store commit
[`16b1667e43c634318a99995c8eb77c23603ae560`](https://github.com/pop-os/cosmic-store/blob/16b1667e43c634318a99995c8eb77c23603ae560/src/main.rs)
treats positional arguments and ActivateAction text as searches; do not invent
`--updates`, `cosmic-store updates`, or an Updates URI. The observed installed Store
version was `1.11.0~1792525498~24.04~16b1667`; the version suffix identifies inspected
source, not a binary attestation.

System76 documents updates for applications installed from configured software
repositories through Store → Updates:
[Installing, Updating, and Removing Applications](https://system76.com/support/managing-apps).
This does not imply global/default Store availability before enrollment.

The archive provides package-derived AppStream collection XML/YAML plus cached
64/128px icon tarballs. APT metadata fetching and offline AppStream validation are
tested. The Store backend reads system `swcatalog`/`app-info` XML/YAML caches;
search discovery depends on the installed distro's AppStream integration. A native
Store search/icon/screenshots trial was not performed for this APT deployment, so
only normal configured-repository system updates are claimed. Terminal installation
remains a documented reliable discovery route after enrollment.

Optional Islands remains an independently requested package. Main installation or
enrollment never pulls it in; an already-installed companion receives normal OS
updates. Existing guarded per-user refresh/next-login behavior remains unchanged.

The original practical 0.2.5 release approval and its explicit limitations are
preserved byte-for-byte. APT trust/retention/bootstrap tests do not fabricate native
UI or hardware acceptance. Final public URL/signature/bootstrap acceptance uses
`scripts/apt/smoke.py` after the parent-approved Pages deployment; it does not touch
host APT, global trust or the live desktop.


## Local 0.3.0 enrollment flow

The development Settings build separates clean manual packages, deliberately
disabled sources, partial enrollment and verified enrollment. Only a clean,
verified manual installation offers **Enable system updates…**. Files are the
exact two pinned bootstrap assets from `scripts/apt/distribution.json`, downloaded
with HTTPS, restricted redirects, size/hash limits and private staging.

`InstallFiles(0, [keyring, source])` uses the OS local-package authorization route.
This is not a retry that disables a failed repository trust check. Both packages
passed the real Noble PackageKit backend in a disposable Ubuntu 24.04 container;
private-bus tests cover early signals, denied authorization, cancellation and
changed files. Host APT was not changed. A graphical PolicyKit prompt as a normal
user remains a real-device acceptance check.

Progress distinguishes preparation, authorization handoff, installation and final
verification. There is no application password field. Halcyon does not cancel or
kill an installation after handing it to PackageKit; cancellation before install
belongs to the system authorization dialog. If the bus disappears or Settings
closes, staging is retained and a new inspection determines the outcome. Manual
instructions use the same verified files; they do not imply enrollment succeeded.

Successful checks retain a last-successful timestamp for the current window,
including after a failed attempt. Stable verified versions link to their own
release tag. COSMIC Store still opens its main window; select Updates there.


## Default enrollment for upcoming packages

The subsequent user decision makes system-update enrollment the default for clean
main-package installs and clean upgrades of older unenrolled manual packages.
`packaging/updates/defaults.py` performs one-time, offline creation from the
reviewed package payload, publishes the source after its key/pins, and records a
public receipt. It never starts apt/dpkg, changes OS unattended-update policy,
installs Islands, starts user services or edits home directories.

Existing bootstrap files and ownership, explicit disable/delete and administrator
configuration are preserved. The Rust identity adapter accepts either the verified
bootstrap or verified main-package templates/receipt; modified, incomplete and
unknown states cannot offer a successful check. The previous interactive installer
remains available for eligible older manual installations. Public bootstrap assets
and distribution pins are unchanged.

Validation: 22 Rust checks, 20 Python checks and nine isolated, network-disabled
package scenarios passed. These cover fresh/manual upgrades, bootstrap migration,
opt-outs, administrator edits, removal and purge. Main package scenarios use a
stub executable; the production Rust release build passed separately. Exact
limitations: `.task-default-updates-evidence/acceptance.json`.
The feature is local; no installed workstation package or published release was changed.
